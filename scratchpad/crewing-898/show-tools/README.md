# Инструменты, которыми поднимается ПОКАЗ четырёх строк (No.898)

Сохранено 05.11 из `/tmp` в проектный скрэтчпад, потому что `/tmp` стирается при загрузке
(`tmpfiles.d`: `D /tmp … 30d` — `D` опустошает каталог на boot). Без этого переноса
единственный инструмент, способный воспроизвести НАСТОЯЩИЙ отказ второй ступени, исчез бы
при перезагрузке, и показ пришлось бы собирать заново.

## Что здесь

- `stub-account.py` — loopback-заглушка: `/api/app/login` → 200 с ответом, проходящим
  `validate()` (первая ступень ДЕЙСТВИТЕЛЬНО успешна), затем `/api/app/crewing/bootstrap`
  падает по содержимому MODE-файла: `unreachable` — сокет закрывается без ответа
  (`post()` send() не проходит → `transport_unreachable` → `workspace_unreachable`);
  `unavailable` — 503 (`upstream_unavailable` → `workspace_unavailable`).
  **Закрытый порт этого дать НЕ МОЖЕТ:** там падает ПЕРВАЯ ступень, это другой сценарий.
- `stub-mode.example` — формат MODE-файла.

дайджестами), dist в бинарнике кадров == dist кандидата, sha

- сборка кадров была DEBUG из копии с loopback dev-origin; релиз не проверялся;
- сервер — наша заглушка, что отвечает настоящий в этих двух случаях, не показано;
- показан только путь отказа второй ступени. **Прежняя оговорка здесь была неверна дважды**,
  и правится 05.11: (1) кода `fresh_context_unavailable` НЕ СУЩЕСТВУЕТ — есть
  `fresh_namespace_unavailable`, он ведёт на текст `workspace_not_created` и к успешному
  входу отношения не имеет; (2) успешный вход НЕ недостижим — стенд 04.11 его прошёл
  (аккаунт сохранён, профиль 600, главный экран показан). Недостижима АКТИВАЦИЯ СЕССИИ:
  `PublicationPolicy::FoundationModel` под `#[cfg(test)]`, поэтому `authorizes()` всегда
  false — это карточка №930, а не свойство этого слайса;
- правка контрастa ДЕСКТОПНАЯ; мобильный путь остаётся 2.79 : 1 (No.925).
