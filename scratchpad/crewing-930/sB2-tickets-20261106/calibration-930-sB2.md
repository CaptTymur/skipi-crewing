# КАЛИБРОВКА исправленного прибора слайса B (No.930)

Прошлый прибор дал ЛОЖНОЕ ОПРОВЕРЖЕНИЕ при ДЕСЯТИ армах калибровки и трёх зелёных
контролях. Диагноз: я калибровал МЕХАНИЗМ и не калибровал ВХОДНОЕ РАЗНООБРАЗИЕ —
фикстуры писал сам, и в них не было ни комментария с иглой, ни локальной переменной-тёзки,
ни `include!`, ни СОСТАВНОГО `cfg`. Поэтому здесь калибровка в два слоя.

## Слой 1 — разбор предиката `cfg` на 12 случаях (вместо подстроки)

```
OK    #[test]                                        ожидали True  получили True
OK    #[cfg(test)]                                   ожидали True  получили True
OK    #[cfg(all(test, target_os = "linux"))]         ожидали True  получили True
OK    #[cfg(any(test, feature = "x"))]               ожидали True  получили True
OK    #[cfg(all(any(test, unix), not(windows)))]     ожидали True  получили True
OK    #[cfg(not(test))]                              ожидали False получили False
OK    #[cfg(all(not(test), unix))]                   ожидали False получили False
OK    #[cfg(target_os = "linux")]                    ожидали False получили False
OK    #[cfg(feature = "testing")]                    ожидали False получили False
OK    #[derive(Debug)]                               ожидали False получили False
OK    #[cfg(all(unix, test))]                        ожидали True  получили True
OK    #[cfg(debug_assertions)]                       ожидали False получили False
случаев 12: положительных 6, отрицательных 6 — обе стороны задействованы
ИТОГ: парсер прошёл все случаи
```

Ключевой случай — `#[cfg(all(test, target_os = "linux"))]`: именно он прятался от
проверки подстрокой `cfg(test)` и стоил круга. Ловушка `feature = "testing"`
(подстрока `test` есть, токена нет) и форма `not(test)` проверены отдельно, то есть
обе стороны задействованы: 6 положительных, 6 отрицательных.

## Слой 2 — калибровка на РЕАЛЬНОМ ВХОДЕ, ожидания выведены НЕЗАВИСИМО

Копия продуктового `src-tauri/src` (21 файл, байтовая сверка с деревом) прогнана
прибором; ожидания получены НЕ из классификатора:

| контроль | независимое правило | измерено |
|---|---|---|
| места `.ticket(` в `native_lifecycle.rs` | строка > 832 (граница тестового модуля) ⇒ ТЕСТОВОЕ | **21 из 21 согласны** |
| `#[tauri::command]` | тестом быть не может | **95 из 95 продуктовыми**, тестовыми 0 |
| `include!` | включённый файл наследует тестовость места включения | `src-tauri/src/native_local_joint_tests.rs` ⇒ место включения тестовое: **True** |

Ворота прибора отказывают (rc 3), если: тестовый модуль НЕ найден разбором `cfg`
(именно его пропустил прошлый прибор — значит контроль задействован, а не пуст);
классификатор расходится с независимым правилом границы хоть на одном месте;
`#[tauri::command]` назван тестовым; определение субъекта не найдено.

## Что исправлено против прошлого прибора

1. тестовость — РАЗБОРОМ предиката `cfg`, не подстрокой;
2. `include!` разбирается, включённый файл наследует тестовость места включения;
3. вызов ищется как ВЫЗОВ МЕТОДА (`.ticket(`), а не как слово;
4. комментарии вырезаются до поиска (с учётом `//` внутри строковых литералов);
5. диапазон определения исключён, поэтому тело самого `fn ticket` не считается вызывающим;
6. `impl PrivateTicket {` и `struct PrivateTicket {` не считаются конструкциями.

**Чего калибровка НЕ доказывает:** она о приборе. И отдельная граница самого ответа:
«в проде нет вызывающего» — утверждение о СТАТИЧЕСКОМ коде; оно не исключает вызова,
появляющегося из макроса или динамики, и такой проверки прибор не делает.
